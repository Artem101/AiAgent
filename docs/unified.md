# Одна модель: говорит, ищет, считает

Четвёртый шаг развития агента. Раньше было две разные вещи:

- агент-браузер, который выбирал действие из латентных мыслей;
- попытка продолжать текст, которая вырождалась в точку.

Теперь это **одна сеть с одним выходом**. Каждая реплика пользователя — эпизод в браузере.
Модель сама решает, что сделать:

- найти ответ в магазине;
- посчитать на Python;
- просто ответить.

Отвечает она фразой, а не одним значением. Разговор не теряется: предыдущие реплики входят в
каждое наблюдение.

Разговор обученной модели в настоящем headless Chromium (`cog_engine chat --browser chrome`),
без правок:

```
Вы     : Привет!
Агент  : Здравствуйте! Чем могу помочь? ✓   (1 шаг., 0.4 с)
Вы     : Как дела?
Агент  : Всё хорошо, спасибо. ✓   (1 шаг., 0.3 с)
Вы     : Сколько стоит лампа?
  · TYPE «лампа»
  · CLICK button «Найти»
Агент  : Сейчас лампа стоит 10 ₽. ✓   (3 шаг., 0.7 с)
Вы     : А сколько будет 12 умножить на 3?
  · CALC «12 * 3»
    = 12 * 3 = 36
Агент  : 12 * 3 = 36 ✓   (2 шаг., 0.5 с)
Вы     : Что дешевле: стул или лампа?
  · TYPE «стул лампа»
  · CLICK button «Найти»
Агент  : Дешевле лампа. ✓   (3 шаг., 0.7 с)
Вы     : Кто ты?
Агент  : Я помощник: ищу в интернете, считаю и отвечаю на вопросы. ✓   (1 шаг., 0.4 с)
Вы     : Что ты умеешь?
Агент  : Ищу товары в магазине, считаю и разговариваю. ✓   (1 шаг., 0.4 с)
Вы     : Спасибо!
Агент  : Пожалуйста! ✓   (1 шаг., 0.3 с)
Вы     : Пока!
Агент  : До свидания! ✓   (1 шаг., 0.2 с)
```

## Что изменилось

| | Шаг 3 (агент-браузер) | Шаг 4 (единая модель) |
|---|---|---|
| Выход | 16 токенов **параллельно**: проба читает действие из латентной мысли | до 32 токенов **по одному**: декодер речи пишет действие или реплику |
| Язык | 1024 токена BPE, обучен на 30 тыс. предложений UD | 8192 токена BPE, обучен на «ru20k» (диалоги, 20 тыс. слов, грамматика) + UD |
| Данные | браузерные задачи + продолжение текста | браузер 35% + диалоги 35% + грамматика 15% + продолжение текста 15% |
| Наблюдение | страница + вопрос + результат калькулятора (128 токенов) | страница + **история разговора** + вопрос + результат калькулятора (160 токенов) |
| Ответ агента | значение: `12`, `стул`, `36` | фраза: «Сейчас лампа стоит 12 ₽.», «Дешевле стул.», «12 * 3 = 36» |
| Реплики | 5 фраз → 5 фиксированных ответов | свободный ответ на любую реплику + несколько вариантов на «Привет!», «Спасибо», «Кто ты?», «Что ты умеешь?» |
| Параметры | 2.05 млн | 7.74 млн |

Латентное рассуждение осталось. Перед каждым действием модель по-прежнему строит план:

- дерево гипотез глубиной 8;
- затем MPPI.

Новое то, что декодер речи **читает весь план** и дописывает ответ токен за токеном, глядя на
каждый токен контекста.

## Архитектура

```text
 наблюдение ─► TTT-энкодер ─► s_0 = E(S_prompt) ─► латентное рассуждение ─► план s_0 … s_8 ─┐
 страница,      W_fast +          цель ĝ = s_0 + G(s_0)   дерево гипотез + MPPI              │
 реплики,       признаки каждого токена [x̃_t ; z_t] ─────────────────────────────────────┐   │
 вопрос,                                                                                  ▼   ▼
 калькулятор                                   декодер речи: каузальный трансформер,
                                               cross-attention к плану и к токенам контекста,
                                               указатель в контекст (копирование)
                                                                                          │
               CLICK [link] ␣лампа <end> · CALC <none> ␣5+5 <end> · ANSWER <none> ␣Привет!·␣Чем·␣помочь? <end>
```

* **TTT-энкодер и JEPA** — те же, что у агента-браузера ([architecture.md](architecture.md),
  [reasoning.md](reasoning.md)). Из наблюдения получается начальная мысль `s_0` и цель `ĝ`.
  Планировщик ищет траекторию латентных состояний, которая по модели мира ведёт к цели.
* **Декодер речи** (`src/speech.rs`) — небольшой pre-LN трансформер: 4 блока шириной 256, 4
  головы.

  ```text
  память  = LN([W_p s_0 + e_0 ; … ; W_p s_8 + e_8 ; W_c [x̃_1 ; z_1] ; … ; W_c [x̃_N ; z_N]])
  h_l     = E[y_{l−1}] + p_l                        (h_0 = E[<bot>] + p_0)
  блок    = h += SelfAttn_causal(LN h);  h += CrossAttn(LN h, память);  h += W_2 ReLU(W_1 LN h)
  P(y_l)  = λ_l · указатель_l + (1 − λ_l) · softmax(LN(h_l) Eᵀ + b)
  ```

  * Память — это девять «мыслей» плана и TTT-признаки всех 160 токенов наблюдения; паддинг
    замаскирован. Ключи и значения памяти считаются один раз и общие для всех блоков.
  * Выходные эмбеддинги связаны с входными.
  * Указатель — механизм копирования из шага 3 ([reasoning.md](reasoning.md)). Он указывает на
    позиции контекста, со сдвигом для копирования подряд идущих токенов, и никогда не указывает
    на спецтокены. Так цена со страницы, название товара или результат калькулятора переносятся
    в ответ, а не выписываются по буквам.
* **Формат выхода не изменился.** Разговор — это действие `ANSWER`, поэтому одна сеть сама
  выбирает между `TYPE`, `CLICK`, `BACK`, `CALC` и ответом.
* **Генерация — инкрементальная.** Ключи и значения самовнимания кэшируются, а распределение
  указателя обновляется по одному шагу. Тест сверяет результат с полным пересчётом.
  Первые два токена (глагол и роль) всегда жадные. Текст реплики в чате сэмплируется с
  температурой 0.7 и top-k 40, у агента — жадно.
* **Запасные гипотезы.** Бывает, что ответ не разбирается как действие или действие уже ничего
  не изменило на странице. Тогда агент по очереди озвучивает выжившие гипотезы дерева поиска и
  берёт первую годную. Если годной нет, он делает несколько сэмплов.

### Наблюдение

```text
[head] ␣Поиск [input] <empty> [button] ␣Найти [link] ␣Каталог <pad>… <user> ␣Привет! <bot> ␣Привет!·␣Чем·␣помочь? <goal> ␣Сколько·␣стоит·␣лампа? CALC …
└──────────────── страница ────────────────┘            └──────── предыдущие реплики ────────┘ └──── текущая реплика ────┘ └ калькулятор ┘
```

160 токенов в таком порядке:

- страница;
- предыдущие реплики: до 56 токенов, сохраняются самые новые;
- текущая реплика: до 40 токенов;
- результат калькулятора: до 24 токенов.

Тест проверяет, что даже самая длинная страница помещается рядом с полной историей.

## Данные: «ru20k»

`scripts/fetch_ru20k.sh` скачивает источники с GitHub за ~10 секунд (другие хосты окружение не
пускает), а `scripts/build_ru20k.py` собирает датасет примерно за минуту. В репозиторий данные
не коммитятся (`data/` в `.gitignore`).

| Источник | Что это | Лицензия |
|---|---|---|
| hermitdave/FrequencyWords `ru_50k.txt` | 50 000 самых частых слов русских субтитров (OpenSubtitles 2018) | CC BY-SA 4.0 |
| Badestrand/russian-dictionary | полные парадигмы ~54 000 лемм openrussian.org: падежи, числа, спряжения, виды, степени | CC BY-SA 4.0 |
| UD_Russian-SynTagRus | 78 500 предложений: художественная литература, новости, научпоп | CC BY-NC-SA 4.0 |
| Koziev/NLP_Datasets | ~1 млн фрагментов диалогов из художественной литературы и ~90 тыс. из анекдотов | как в репозитории-источнике |
| UD Russian GSD + Taiga (`scripts/fetch_ru_corpus.sh`) | 31 600 предложений Википедии, новостей, веба | CC BY-SA 4.0 |

Что строится:

* **20 000 слов.** Самые частые слова без мата и мусора субтитров (нет гласной — не слово);
  `ё` = `е`.
* **Примеры употребления.** К каждому слову подобрано до пяти предложений из UD, SynTagRus и
  реплик диалогов, от 3 до 25 слов. Примеры есть у **19 659 слов (98.3%)**, пять и больше — у
  18 013 (90%). Без примеров остаются в основном имена и обрывки субтитров («чжин», «шелдон»).
  Всего 64 812 предложений (+ UD).
* **Грамматические вопросы.** 37 300 вопросов о 16 841 слове списка (через их леммы), 17 видов:
  - падежи: «Как будет «инициатива» в дательном падеже?» → «инициативе»;
  - склонение, множественное число, род;
  - спряжение, прошедшее время, вид и видовая пара, повелительное наклонение;
  - формы прилагательных и сравнительная степень.

  10% лемм отложены: вопросов о них модель не видит, и на них проверяется обобщение.
* **Диалоги.** 910 059 пар «контекст (1–3 реплики) → ответ».
  - Реплики из художественной литературы и анекдотов, не длиннее 120–150 символов.
  - Не меньше 80% кириллических букв.
  - Мат отфильтрован. Фильтр проверяется списком слов, которые он не должен задевать:
    «требует», «хлебу», «небо», «себе».

  1% отложен для оценки.

**Токенизатор.** 8192 токена: 20 спецтокенов, из них новые `<user>` и `<bot>`, плюс 256 байтов
и 7916 слияний. Обучен на выборке из «ru20k» (700 тыс. строк) и текстах браузерных задач за 12
секунд.

- 91% из 1000 самых частых слов — один токен.
- 20 тыс. слов в среднем занимают 2.18 токена.
- Отложенные предложения UD — 2.96 символа на токен, реплики диалогов — 3.17. У прежних
  1024 токенов было 1.93 и 1.89: тот же текст стал в 1.5–1.7 раза короче.

**Смесь обучения** (`src/dialog.rs`). Каждый пример — наблюдение агента и то, что он должен
сделать.

| Источник | Доля | Наблюдение | Выход |
|---|---:|---|---|
| браузер | 35% | страница + иногда посторонние реплики + задача + результат калькулятора | действие учителя |
| диалог | 35% | страница магазина + предыдущие реплики + реплика собеседника | `ANSWER` + ответ из книги или анекдота |
| грамматика | 15% | страница магазина + вопрос о слове (иногда после посторонних реплик) | `ANSWER` + форма(ы) |
| текст | 15% | `<text>` + начало предложения | продолжение до 31 токена + `<end>` |

Посторонние реплики в браузерных задачах и в вопросах по грамматике учат не путать историю
разговора с текущим вопросом.

**Ответы учителя** стали фразами (`goal::say`):

| Семейство | Ответ |
|---|---|
| lookup | «Сейчас лампа стоит 12 ₽.», «Цвет — красный.», «Бренд — Nova.», «Рейтинг — 4 ★.» |
| compare | «Дешевле стул.», «Дороже часы.», «По рейтингу лучше лампа.» |
| filter | «Например, зонт.» |
| calc | «12 * 3 = 36» (строка калькулятора) |
| total | «Вместе 19 ₽.», «Дороже на 5 ₽.» |
| chat | один из 2–3 ответов на каждую из шести фраз |

Проверка ответа (`Spec::accepts`) извлекает из фразы то, что в ней утверждается:

- для цены и рейтинга — ровно одно число, и оно верное;
- для цвета и бренда — ровно одно значение атрибута;
- для сравнения и фильтра — первый названный товар в любом падеже;
- для вычислений — последнее число;
- для реплик — ключевые слова: «привет», «здравств», «хорош», «пожалуйста»…

Ответы-значения, как у прежней модели, тоже засчитываются.

## Обучение

```text
L = NLL_речь(y | план, контекст) + 1.0 · L_указатель + L_JEPA (VICReg + цель + BC политики)
```

* **План, на котором учится декодер.** В 70% примеров это роллаут политики из `s_0`, то есть
  жадная цепочка мыслей, которую планировщик уточняет на инференсе. В остальных 30% это
  teacher-forced план: он видел ответ, но и учит модель мира, и помогает декодеру читать мысли.
  К плану добавляется шум (σ = 0.05). Потеря JEPA учит латентное пространство так же, как у
  агента-браузера.
* **AdamW.** Пик lr 1e-3, 300 шагов прогрева, косинус до 5e-5, клиппинг градиента 1.0.
  Батч — 64 примера.
* **Ход обучения.**
  - **Шаги 0–4500:** первые шаблоны ответов («Лампа стоит 12 ₽.»).
  - **Шаги 4500–8000:** продолжение с тех же весов на исправленных данных:
    - названия товаров в ответе стоят строчными в середине фразы («Сейчас лампа стоит 12 ₽.»).
      Заглавная «Лампа» — другой токен, чем « лампа», и указатель не мог его скопировать:
      модель называла не тот товар («Рюкзак стоит 10 ₽.»);
    - в вопросах появились вариации регистра («Сколько стоит Лампа?», «СКОЛЬКО СТОИТ ЛАМПА»),
      чтобы модель понимала заглавные буквы.
  - **Отжиг:** 1000 шагов с lr от 3e-4 до 2e-5.
  - **Итого:** 9000 шагов по 64 примера, 576 тыс. примеров, около 6.5 ч на 4 ядрах CPU.

**Скорость на CPU.** Обучение шло на 4 ядрах без GPU. Первая версия делала 0.2 шага/с при
батче 32; три изменения подняли скорость до 0.47 шага/с при батче 64, то есть в 4.7 раза по
числу примеров:

1. **Микробатчи на ядрах.** В candle поэлементные операции на CPU однопоточные. Батч делится на
   4 части, каждое ядро считает свою часть до обратного прохода, градиенты усредняются
   (`UnifiedTrainConfig::workers`).
2. **Аллокатор.** candle выделяет новый буфер на каждую операцию, и с настройками glibc по
   умолчанию каждый большой буфер — это новый `mmap`, страницы которого заново проходят через
   page fault. Три вызова `mallopt` в начале `main` держат освобождённую память в процессе:
   ×1.7.
3. **Дешёвые блоки.** Проекции без bias (их градиент — медленная редукция по батчу), ReLU
   вместо GELU (GELU в candle на CPU в 5 раз медленнее), общие для всех блоков ключи и
   значения памяти. Проход вперёд и назад по декодеру ускорился в 2.7 раза.

**Язык.**

- **Потери на отложенных данных** (256 примеров на источник, нат на токен; в скобках — доля
  верных самых вероятных токенов):
  - действия браузера — 0.75 (59%);
  - диалоги — 3.55 (43%);
  - грамматические вопросы — 1.93 (64%);
  - продолжение текста — 5.62 (16%).
- **Грамматика.** Точный ответ на 17% вопросов об отложенных словах и на 16% вопросов об
  обучающих. По видам вопросов:
  - род — 65%, вид глагола — 60%;
  - падежные формы — 4–15%;
  - полное склонение и спряжение (5–6 форм подряд) — 0%.

  Одиночная категория (род, вид) выучена, порождение форм — только начато.
- **Разговор.** На известные реплики модель отвечает по делу и с вариациями:

| Реплика | Ответ модели (жадно) |

| Привет! | Привет! Что найти или посчитать? |
| Как дела? | Всё хорошо, спасибо. |
| Кто ты? | Я помощник: ищу в интернете, считаю и отвечаю на вопросы. |
| Что ты умеешь? | Умею искать в браузере, считать на калькуляторе и отвечать на вопросы. |

| Мне грустно. | А что? |
| Какое множественное число у слова «друг»? | фы |

На свободные реплики из книг ответы короткие и общие: «А что?», «Я не знаю.», «А ты?». Это
типично для модели на 7.7 млн параметров после 200 тыс. увиденных диалогов. Грамматически
ответы правильные, но по смыслу с репликой собеседника почти не связаны.

## Как пользоваться

```bash
cargo build --release
# данные (≈200 МБ, ~10 с) и сборка датасета (~1 мин)
scripts/fetch_ru_corpus.sh && scripts/fetch_ru20k.sh && python3 scripts/build_ru20k.py
# поговорить с моделью (по умолчанию models/agent.safetensors, браузер — симулятор)
./target/release/cog_engine chat
./target/release/cog_engine chat --browser chrome --think          # настоящий Chromium, показать рассуждение
./target/release/cog_engine chat --say "Привет!|Сколько стоит лампа?|Спасибо!"
# один вопрос агенту, с рассуждением на каждом шаге
./target/release/cog_engine agent --question "Что дешевле: лампа или стул?"
# оценка: потери по источникам, грамматика, реплики, агент на 2×200 задачах
./target/release/cog_engine unified-eval
# обучение с нуля (~6 ч на 4 ядрах CPU)
./target/release/cog_engine train-unified --steps 10000 --batch 64 --out models/agent.safetensors
```

Из кода — `examples/browser_agent.rs`:

```bash
cargo run --release --example browser_agent -- models/agent.safetensors "Привет!|Сколько стоит лампа?|Спасибо!"
```

## Ограничения

* **Свободный разговор однообразен.** Модель выучила формы и частые ответы, но не содержание
  реплик. Это следующий шаг: пресет L на 22 млн параметров
  ([scaling.md](scaling.md)).
* **История разговора.** В обучении история состояла из реплик книг. После вопросов к
  агенту, то есть поиска и вычислений, модель путает следующую реплику с прошлой задачей. Поэтому
  `chat` для этой модели сохраняет в истории только разговорные обмены. В обучении L история
  уже содержит прошлые вопросы агенту с его ответами.
* **Новые формулировки.** На отложенных шаблонах решается 20% задач. «Во сколько обойдётся
  лампа?» модель принимает за реплику и отвечает сразу, не ища.
* **Формы слов.** Склонение и спряжение целиком (5–6 форм) не выходят, отдельные падежи — в
  4–15% случаев.
* **Сэмплирование** в чате (температура 0.7, top-k 40, штраф за повтор слов 1.5) действует
  только на текст реплики. Запросы, выражения и нажатия всегда жадные, иначе в них попадал
  мусор («стул ЛА6»).
