# Обучение

## Быстрый запуск

```bash
cargo run --release -- train --task sort --steps 1500 --out model.safetensors
```

Или из кода (`examples/quickstart.rs`):

```rust
let model = CogModel::new(EngineConfig::tiny(10, 8, 8), &Device::Cpu)?;
let mut trainer = Trainer::new(model, TrainConfig::quick(Task::Sort))?;
trainer.run(|line| println!("{line}"))?;   // логи, периодическая оценка
trainer.model.save("model.safetensors")?;
```

`Trainer::train_step()` делает один шаг, если нужен собственный цикл. Он возвращает
`(LossReport, норма градиента до клиппинга)`.

## Что происходит на одном шаге

1. `TaskSampler::batch` генерирует `B` пар (промпт, ответ) из RNG-потока `(seed, 0x7EA1, 0)`.
2. `CogModel::loss`:
   * TTT сканирует `[промпт ; ответ]` и снимает `H + 1` readout'ов на границах чанков;
   * JEPA строит цели `s̄_h`, teacher-forced траекторию `ŝ_h` и свои потери;
   * проба мыслей (если есть) декодирует `s_0`, `s_H` и случайные промежуточные мысли в ответ,
     с копированием из промпта (если `copy_dim > 0`);
   * CFM сэмплирует `t`, `X_0` и считает `L_CFM`, `L_ce`, `L_head` при условии на траекторию.
3. `backward`, глобальная норма градиента, клиппинг до `grad_clip`.
4. AdamW-шаг с learning rate по расписанию: линейный warmup `warmup` шагов, затем косинус от
   `lr` до `min_lr`.
5. EMA-обновление целевого энкодера `Ē_θ`.

Формулы всех слагаемых — в [math.md](math.md).

## Как читать лог

```
step  1500 | loss 0.2369 | cfm 0.0418 ce 0.0148 head 0.0105 | inv 0.0170 var 0.0700 cov 1.8209 goal 0.0046 π 0.0606 | |g| 0.760 | lr 1.00e-4 | 6.7 step/s
```

Значения усреднены за последние `log_every` шагов.

| Поле | Что это | Типичная динамика (`tiny`, sort) |
|---|---|---|
| `loss` | полная взвешенная сумма | 2.5 → 0.2 |
| `cfm` | ошибка векторного поля — главный сигнал декодера | 1.4 → 0.04 |
| `ce` | CE по одношаговой оценке `x̂_1` | 1.8 → 0.015 |
| `head` | CE головки на зашумлённых чистых эмбеддингах | 1.7 → 0.01 |
| `inv` | MSE между траекторией и целями JEPA | ≈ 0.03 → 0.017 |
| `var` | штраф VICReg за «схлопнутые» измерения | 0.7 → 0.07: стандартные отклонения латентов подтягиваются к 1 |
| `cov` | сумма квадратов ковариаций между измерениями | растёт 0.16 → ~2. План становится информативным и измерения коррелируют; с весом 0.04 это ≈ 0.08 в `loss` |
| `goal` | ошибка предсказания цели `ĝ` | ≈ 0.005 |
| `π` | behaviour cloning политики | растёт по мере того, как действия модели латентных действий становятся разнообразнее (0.003 → ~0.1), затем снижается (~0.06) |
| `\|g\|` | глобальная норма градиента до клиппинга | ≈ 1 |
| `lr` | текущий learning rate | |
| `step/s` | скорость обучения | ≈ 7–8 на 4 ядрах CPU (`tiny`, f32, batch 64) |

**Признаки проблем:**
* `var` не падает или растёт к 1 — латентное пространство коллапсирует. Увеличьте `var_weight`.
* `cfm` застрял выше ~0.5 — декодеру не хватает сигнала от плана. Проверьте `plan_noise` и размеры.
* `|g|` постоянно на порядок выше `grad_clip` — уменьшите `lr`.

## Оценка

Каждые `eval_every` шагов (и в конце) `Trainer::evaluate(n, seed)` берёт `n` новых примеров из
отдельного RNG-потока и печатает:

```
step  1500 | eval n=128 | oracle plan: tok 97.9% seq 84.4%
           engine π+MPPI    tok  96.8% seq  80.5% | energy 0.0120 (warm start 0.0232) |   8948 µs/query
             π only         tok  95.2% seq  71.9% | energy 0.0232 (warm start 0.0232) |   4394 µs/query
             MPPI (zero init) tok  83.8% seq  37.5% | energy 0.0128 (warm start 0.0366) |   8611 µs/query
```

| Строка | Что измеряет |
|---|---|
| `oracle plan` | Декодер (graph path, batch) получает teacher-forced траекторию, построенную с доступом к ответу. **Верхняя граница** для любого планировщика |
| `engine π+MPPI` | Полный движок по умолчанию на упакованных bf16-весах: TTT → π-роллаут → MPPI → CFM |
| `π only` | Абляция: `iterations = 0`, план — роллаут политики без поиска |
| `MPPI (zero init)` | Абляция: MPPI без политики, с нулевого тёплого старта |

`tok` — доля верных токенов, `seq` — доля ответов, верных целиком. `energy` — энергия
итогового плана, в скобках — энергия тёплого старта. Разрыв между `oracle` и `engine` —
это ошибка планирования. Разрыв между `engine` и `π only` — вклад поиска.

## Точность вычислений и устройство

| Флаг / поле | Значение |
|---|---|
| `--compute auto` (`compute_dtype: None`) | f32 на CPU, bf16 на CUDA |
| `--compute f16` | работает на CPU, но в ~2.4 раза медленнее f32: в candle нет быстрого CPU-GEMM для f16 |
| `--compute bf16` | для CUDA. **На CPU не работает**: в candle 0.11 нет CPU-matmul для bf16 |
| `--device cuda` | требует сборки с `--features cuda`. **Не проверялось** — в среде разработки не было GPU |

Мастер-веса, моменты AdamW и накопление градиентов всегда в f32, независимо от compute dtype.
LayerNorm, softmax, VICReg и cross-entropy всегда считаются в f32.

## Воспроизводимость

Обучение полностью детерминировано на CPU: инициализация, данные и шум идут из собственного
seeded RNG, а не из `rand` внутри candle. Один и тот же `--seed` даёт бит-в-бит одинаковые значения потерь и метрик.
`--seed` одновременно задаёт инициализацию весов и поток данных.

## Чекпойнты

`CogModel::save(path)` пишет один safetensors-файл:

| Префикс ключа | Содержимое |
|---|---|
| `online.<имя>` | все обучаемые параметры (`ttt.*`, `jepa.*`, `flow.*`, `head.*`) |
| `target.<имя>` | EMA-энкодер `jepa.ctx_enc.*` и замороженная таблица `buffers.out_emb` |

`CogModel::load(path)` требует модель **той же архитектуры**: сначала создайте её из того же
`EngineConfig`, потом загрузите веса. CLI рядом с чекпойнтом пишет `<ckpt>.cfg` (пресет,
словарь, длину, задачу, seed), чтобы `infer`/`bench`/`serve` могли воссоздать конфигурацию.

## Задачи

| `--task` | Ответ | Что проверяет |
|---|---|---|
| `sort` (по умолчанию) | промпт, отсортированный по возрастанию | мешок токенов → упорядоченная последовательность; хорошо ложится на ассоциативную память TTT |
| `reverse` | промпт задом наперёд | нужна позиционная информация в `W_fast` |
| `copy` | промпт без изменений | санити-чек |
| `browser` | следующее действие агента по русской инструкции | агент-браузер: чтение страницы, навигация, сравнение чисел, фильтр, калькулятор, реплики ([browser.md](browser.md), [calculator.md](calculator.md)) |
| `text` | следующие 16 BPE-токенов русского предложения | продолжение текста на корпусе (`--corpus`), см. [reasoning.md](reasoning.md) |

`sort/reverse/copy` требуют `N = L` (`--len`). У `browser` и `text` размеры фиксированы: словарь
BPE (1024 токена), `N = 128`, `L = 16`. Для них `train` включает окно в TTT, readout по вопросу,
gated pools, пробу мыслей с копированием, горизонт 8 и латентное дерево. С `--corpus` к
браузерным примерам примешивается 25% продолжения текста (`--text-mix`). В конце печатаются точность продолжения
текста на `--valid` против базовых линий, точность шагов по типам действий и успешность на 200
эпизодах в симуляторе — для обучающих и для отложенных формулировок.

## Советы по гиперпараметрам

* **Больше шагов почти всегда лучше**: к 1500 шагам `tiny` ещё не сошёлся (oracle 84% по
  последовательностям). Для 2000–3000 шагов увеличьте `steps`, остальное менять не нужно.
* **`plan_noise`** (0.05) делает декодер устойчивее к неточным планам. При большом разрыве
  oracle ↔ engine попробуйте 0.1.
* **`horizon`** должен делить `L`: каждый шаг плана при обучении соответствует `L/H` токенам ответа.
* **Потоки.** Для `tiny` на CPU один поток быстрее четырёх: на задаче `browser` 11.5 против
  7.9 шагов/с. Матрицы слишком малы, и накладные расходы rayon перевешивают. Запускайте
  `RAYON_NUM_THREADS=1`, а свободные ядра отдайте параллельным запускам (другие сиды, абляции).
  Бит-в-бит воспроизводимость обучения гарантируется при одинаковом числе потоков.
* **Пресет `small`** больше `tiny` в 4 раза по параметрам (браузер: 2.05M против 0.49M) и
  медленнее примерно в 2.4 раза (0.5 против 1.2 шага/с в один поток, `N = 128`, `L = 16`). Для
  браузерного агента с копированием используется `small`.
* **Где время шага** (`tiny`, браузер, один поток): прямой проход ≈ 230 мс (TTT ≈ 110, проба ≈ 45,
  CFM ≈ 60), backward ≈ 600 мс. Проба по всем 9 мыслям стоила бы 150 мс прямого прохода, поэтому
  `--probe-states 3`.
* **Прерванный прогон** продолжается с последнего промежуточного чекпойнта:
  `--init out.step4000 --start-step 4000` с теми же остальными флагами.
