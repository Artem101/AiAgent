# Спецификация: модель на 10–25 млн параметров и школьный датасет

Документ описывает следующий шаг после единой модели ([unified.md](unified.md)):

- **Ёмкость.** Модель вырастает до 14 млн параметров (пресет **M**) или 24 млн (**L**).
- **Данные.** Она учится на школьной программе 1–7 классов по русскому языку и математике.
- **Формат обучения.** Только структурированные цепочки рассуждений «вопрос → шаг мышления →
  инструмент → ответ», без сырых текстов. Браузерные траектории сохраняются.

Что уже готово в репозитории:

- **пресеты M и L** в коде: `cog_engine unified-params` считает их параметры;
- **датасет:** `scripts/fetch_school.sh`, `scripts/build_school.py`, `cog_engine export-trajectories`;
- **этот документ.**

Что нужно реализовать, перечислено в разделе [«Изменения в коде»](#изменения-в-коде).

## 1. Размеры модели

Числа параметров посчитаны кодом (`cog_engine unified-params`, словарь 8192 токена):

| | **base** (сейчас) | **M** | **L** |
|---|---:|---:|---:|
| формат наблюдения / действия (раздел 2) | V1: 160 / 32 | V2: 320 / 64 | V2: 320 / 64 |
| словарь | 8192 | 8194 (+ `THINK`, `LOOKUP`) | 8194 |
| **TTT-энкодер**: `d_model` / `d_fast` / `d_ctx` | 128 / 64 / 192 | 160 / 96 / 256 | 128 / 64 / 192 |
| причинное окно, последние выходы, пулы | 4 / 4 / 4 | 4 / 4 / 4 | 4 / 4 / 4 |
| **латентный планировщик**: `d_state` / `d_action` / `d_hidden` | 64 / 16 / 256 | 96 / 24 / 384 | 128 / 32 / 512 |
| горизонт `H`, дерево гипотез (луч × ветви), MPPI | 8, 4 × 4, 256 × 8 | 8, 4 × 4, 256 × 8 | 8, 4 × 4, 256 × 8 |
| **декодер речи**: `d_model` × слоёв, головы, MLP | 256 × 4, 4, ×4 | 320 × 6, 5, ×4 | 512 × 4, 8, ×4 |
| ключ указателя (копирование) | 32 | 48 | 32 |
| параметров TTT | 1.44 млн | 2.08 млн | 1.46 млн |
| параметров JEPA | 0.21 млн | 0.46 млн | 0.74 млн |
| параметров декодера | 6.09 млн | 11.74 млн | 19.82 млн |
| из них эмбеддинги токенов (TTT + декодер) | 3.15 млн | 3.93 млн | 5.24 млн |
| **всего** | **7.74 млн** | **14.28 млн** | **22.03 млн** |
| файл весов (f32) | 31 МБ | 57 МБ | 88 МБ |

**L выращивается из обученной base** (`cog_engine train-unified --grow-from base.safetensors`,
раздел 5). Поэтому ширина TTT-энкодера у L та же, что у base: её нельзя расширить без изменения
функции модели, так как ридаут нормирует признаки по всей ширине. Память о контексте у L та же,
`W_fast` 64 × 64, а длинное наблюдение формата V2 она читает через копирование и внимание
декодера к каждому токену. M учится с нуля и получает более широкий энкодер.

**Куда идёт ёмкость и почему.**

* **Декодер речи** получает 80–85% параметров. Именно он отвечает за язык: у base потери на
  диалогах выходят на плато около 3.9 нат на токен, реплики однообразны, формы слов путаются.
  - В **M** декодер глубже (6 слоёв вместо 4) и немного шире (320 вместо 256). Глубина помогает
    многошаговым цепочкам: нужно держать в голове условие, черновик шагов и формат ответа.
  - В **L** декодер вдвое шире (512) при той же глубине. Это ровно удвоенная base, поэтому L
    можно вырастить из обученной base без потери выученного (раздел 5).
* **Планировщик** расширяется пропорционально: `d_state` 64 → 96 → 128. Латентное состояние
  описывает, в какой точке решения находится агент. Решения в несколько действий (CALC, потом
  LOOKUP, потом ответ) требуют больше таких «координат», чем выбор одного действия в браузере.
  Горизонт `H = 8` и размеры дерева гипотез не меняются: время «мышления» на CPU остаётся в
  пределах десятков миллисекунд.
* **TTT-энкодер** у M: `d_fast` 64 → 96. Матрица быстрых весов — вся память о контексте, а
  наблюдение вырастает вдвое (раздел 2), так что её память растёт в 2.25 раза.
* **Эмбеддинги.** Словарь остаётся на 8192 токенах, плюс два новых спецтокена (раздел 3).
  Токенизатор на 8192 уже даёт 91% частых слов одним токеном. Больший словарь ушёл бы в
  эмбеддинги, а не в «мышление».

## 2. Форматы наблюдения и действия

Длины частей школьных цепочек в токенах (6000 случайных примеров, токенизатор на 8192):

| Часть | медиана | 95-й процентиль | 99-й процентиль | максимум |
|---|---:|---:|---:|---:|
| вопрос | 16 | 41 | 49 | 98 |
| шаг мышления (THINK) | 23 | 48 | 56 | 70 |
| статья словаря (результат LOOKUP) | 46 | 62 | 69 | 79 |
| ответ | 9 | 19 | 29 | 73 |
| все предыдущие шаги цепочки | 41 | 97 | 117 | 145 |
| шагов в цепочке | 3 | 5 | 7 | 7 |

Отсюда новые размеры:

| | сейчас | M и L |
|---|---:|---:|
| наблюдение `N` | 160 | **320** |
| страница (обрезается первой) | ≤ 46 | ≤ 46 |
| история разговора | ≤ 56 | ≤ 56 |
| текущая реплика / вопрос `GOAL_MAX` | ≤ 40 | **≤ 64** |
| черновик — последние шаги агента `SCRATCH_MAX` (вместо одного результата калькулятора) | ≤ 24 | **≤ 128** |
| действие `L` | 32 | **64** |

Черновик — это последние шаги эпизода, самые новые в конце, рядом с ридаутом TTT: мысли
(`THINK`), вызовы инструментов с ответами (`CALC`, `LOOKUP`) и сделанные действия в браузере
(`CLICK [button] ␣Найти`, `TYPE [input] ␣лампа`). Последнее нужно, чтобы агент помнил, что уже
сделал, и чтобы после действия снова «подумал».

```text
… <goal> ␣В·␣двух·␣корзинах·␣135·␣яблок… THINK ␣Пусть·␣во·␣второй·␣x… CALC ␣135·␣/·␣5·␣=·␣27 THINK ␣Во·␣второй·␣27…
```

Он заменяет нынешнюю одну запись калькулятора. В браузерных задачах в черновик попадают вызовы
калькулятора и шаги мышления, в школьных — ещё и статьи словаря.

## 3. Действия и инструменты

| Действие | Что делает | Что появляется в наблюдении |
|---|---|---|
| `THINK <none> текст <end>` | **новое**: шаг рассуждения вслух | запись `THINK текст` в черновике |
| `CALC <none> выражение <end>` | калькулятор на Python (как сейчас) | `CALC выражение = результат` |
| `LOOKUP <none> слово <end>` | **новое**: морфологический словарь | `LOOKUP слово → статья` |
| `CLICK`, `TYPE`, `BACK` | браузер (как сейчас) | новая страница |
| `ANSWER <none> текст <end>` | ответ, конец эпизода | — |

**Словарь для LOOKUP** — `data/school/dictionary.jsonl`, 47 868 статей. Собирается скриптом
`build_school.py` из трёх источников:

- **openrussian.org:** род, одушевлённость, склонение существительных; вид, спряжение и
  видовая пара глаголов; формы, краткая форма и сравнительная степень прилагательных;
- **морфемный словарь Тихонова:** 93 тыс. разобранных слов — приставка, корень, суффиксы,
  окончание, постфикс, соединительная гласная;
- **UD SynTagRus:** части речи неизменяемых слов (наречия, предлоги, союзы, частицы,
  местоимения, числительные).

Пример статьи:

```
подснежник — существительное, м. р., неодуш., 2-е скл.; состав: под-снеж-ник-∅ (приставка под, корень снеж, суффикс ник, окончание нулевое)
```

Поиск по слову без учёта регистра и `ё`/`е`. Если слова нет, инструмент возвращает «нет в
словаре», и агент должен рассуждать сам: в обучающих цепочках LOOKUP вызывается только для
слов из словаря.

**Токенизатор.** Два новых спецтокена, `THINK` и `LOOKUP`, дописываются в конец словаря под
номерами 8192 и 8193, а не перенумеровывают его. Тогда растущая модель сохраняет все
выученные эмбеддинги.

## 4. Датасет

### Школьные цепочки: `data/school/chains.jsonl`

Одна задача — одна строка JSON:

```json
{"id": "m4_meeting_00017", "grade": 4, "subject": "математика", "topic": "движение навстречу и вдогонку",
 "split": "train", "question": "Два велосипедиста выехали одновременно навстречу друг другу …",
 "steps": [
   {"act": "THINK",  "text": "Они едут навстречу, поэтому за час расстояние между ними сокращается на 12 + 15 км — это скорость сближения."},
   {"act": "CALC",   "text": "12 + 15", "result": "27"},
   {"act": "THINK",  "text": "Время встречи = расстояние : скорость сближения."},
   {"act": "CALC",   "text": "81 / 27", "result": "3"},
   {"act": "ANSWER", "text": "Они встретятся через 3 ч."}],
 "check": {"type": "number", "value": "3"}}
```

Правила сборки:

* **Сырых абзацев нет.** Каждый пример — вопрос и цепочка шагов.
* **Результаты CALC.** Они посчитаны той же программой, что у Python-калькулятора агента
  (точные дроби, печать до 4 знаков). Все выражения укладываются в грамматику калькулятора:
  `+ - * /`, скобки, десятичные дроби. Степени и НОД выражаются через умножение.
* **Шаги мышления.** Они объясняют логику условия, а не повторяют ответ:
  - что известно и что спрашивается («на 3 больше — значит складываю»);
  - почему выбрано это действие («Неизвестное уменьшаемое = разность + вычитаемое»);
  - косвенные формулировки («У Маши на 4 больше, значит у Пети на 4 меньше: вычитаю, а не
    складываю»);
  - проверки: подстановка корня в уравнение.
* **Задачи по языку.** Где нужно знание о слове, модель вызывает LOOKUP. Где нужно правило, в
  THINK формулируется правило и применяется к слову: склонение по роду и окончанию, спряжение
  по форме «они …», падеж по вопросу от главного слова.
* **Задачи по предложениям.** Падеж, время, лицо, часть речи в контексте, подлежащее и
  сказуемое, причастия и деепричастия, служебные слова. Предложения берутся из SynTagRus с
  эталонной разметкой: до 12 слов, без цифр, латиницы и мата.
* **Разбиение.** 3% — valid и 3% — test. Для языка откладываются целые слова (лемма не
  встречается в обучении) или целые предложения, для математики — целые формулировки.
* **Ключ проверки `check`** — число или текст, который должен содержаться в ответе.

**Состав:** 181 959 цепочек, 559 131 шаг — 211 335 THINK, 139 239 CALC, 26 598 LOOKUP,
181 959 ANSWER; train 171 040, valid 5 351, test 5 568. Число задач по темам лежит в
`data/school/stats.txt`, основные темы:

| Класс | Математика | Русский язык |
|---|---|---|
| 1 | сложение и вычитание в пределах 20, сравнение, задачи «было — стало», «на сколько больше / меньше», в том числе косвенные | слоги, буквы и звуки (е, ё, ю, я, ь, ъ), большая буква в именах собственных |
| 2 | сложение и вычитание в пределах 100 по разрядам, смысл умножения и деления, единицы величин, задачи в два действия, периметр | части речи (существительное, прилагательное, глагол) + LOOKUP, род существительных |
| 3 | табличное умножение и деление, деление с остатком, порядок действий, площадь, цена — количество — стоимость, доля числа | состав слова + LOOKUP, корень, падеж в предложении, время глагола |
| 4 | многозначные числа, скорость — время — расстояние, движение навстречу, в противоположных направлениях, вдогонку, единицы времени, часть от целого, уравнения с проверкой | склонение существительных, спряжение глаголов (+ LOOKUP), лицо и число |
| 5 | десятичные дроби, дроби с одинаковыми знаменателями с сокращением, проценты, объём, среднее арифметическое, число по его части, округление | части речи в предложении (все 12), подлежащее и сказуемое |
| 6 | НОД и НОК через разложение на множители, признаки делимости, пропорции, отрицательные числа, изменение на процент, деление в отношении, окружность и круг, умножение и деление дробей | вид глагола (+ LOOKUP), сравнительная степень |
| 7 | линейные уравнения, уравнения с неизвестным в обеих частях, значение линейной функции, степени, системы уравнений, задачи на составление уравнения, углы треугольника | причастия (действительное / страдательное, время, краткость), деепричастия (вид), служебные части речи |

### Браузерные траектории: `data/school/browser.jsonl`

Команда `cog_engine export-trajectories --n 20000` выгружает эпизоды учителя в симуляторе в
том же формате: 20 000 эпизодов (90% с обучающими формулировками, 10% с отложенными) и
114 130 шагов. На каждое действие приходится шаг THINK с причиной, например «Запрос введён —
нажимаю «Найти»», «В этой строке каталога товар подходит под условие». Для каждого действия
записаны страница, на которой оно сделано, и адрес:

```json
{"act": "CALC", "text": "16 - 10", "result": "6", "url": "/w/373250/search?q=…",
 "page": "[heading] Результаты | [input] клавиатура шлем | [button] Найти | [link] стул | [value] 11 ₽ | …"}
```

Генератор браузерных задач в Rust остаётся источником бесконечных свежих траекторий: миры
случайны, выгрузка — фиксированный срез для воспроизводимости и проверки.

### Смесь обучения M и L

Цепочки разворачиваются в примеры по шагам. Пример — это наблюдение со всеми предыдущими шагами
в черновике и следующее действие: цепочка из `k` шагов даёт `k` примеров.

| Источник | Доля | Примеров-шагов |
|---|---:|---:|
| школьные цепочки | 35% | 559 тыс. |
| браузерные траектории (свежие из генератора, с THINK) | 25% | ∞ (срез — 114 тыс.) |
| диалоги «ru20k» | 25% | 910 тыс. |
| грамматические вопросы «ru20k» | 5% | 37 тыс. |
| продолжение текста | 10% | 96 тыс. предложений |

**Учебный план.** Первые 20% шагов обучения берутся только из 1–3 классов плюс браузер и
диалоги, следующие 30% — из 1–5 классов, остальное — из всех классов. Лёгкие задачи учат
формату цепочки, трудные — содержанию.

## 5. Как вырастить модель

**L из обученной base — рекомендуемый путь.** Ширина декодера удваивается (256 → 512) без
изменения функции модели. У декодера LayerNorm без параметров, поэтому ширину можно удвоить
дублированием:

* **Остаточный поток.** Вектор `x` превращается в `[x ; x]`: среднее и дисперсия не меняются,
  значит `LN([x ; x]) = [LN(x) ; LN(x)]`.
* **Линейный слой `y = W x`, который читает поток.** Становится `W' = [W/2, W/2]`, выход тот
  же.
* **Слой, который пишет в поток.** Выходы дублируются: `W' = [[W/2, W/2]; [W/2, W/2]]`.
* **Внимание.** 4 головы по 64 превращаются в 8 голов по 64: 4 исходные и 4 копии с
  одинаковыми весами Q, K, V. Внимание каждой копии совпадает с исходным.
* **MLP.** Скрытый слой 1024 → 2048 дублируется, ReLU сохраняет дубли.
* **Эмбеддинги токенов** `[E ; E]`. С общими входными и выходными эмбеддингами логиты
  удваиваются, поэтому в декодер добавляется масштаб логитов `s`: 1 у base, ½ после удвоения.
* **Указатель** остаётся с ключом 32. Запросы указателя читают поток через `[W/2, W/2]`.
* **Нарушение симметрии.** После удвоения к копиям добавляется шум порядка 1e-3, иначе они
  так и останутся одинаковыми.

**Планировщик** расширяется дополнением нулями: `d_state` 64 → 128, `d_action` 16 → 32,
`d_hidden` 256 → 512. Новые строки каждого слоя и новые столбцы для новых входов равны нулю.
Поэтому новые измерения состояния и действия остаются нулевыми (GELU(0) = 0, модель мира
остаточная), а старые считаются в точности как раньше.

**TTT-энкодер** не расширяется. Его ридаут нормирует признаки по всей ширине, и дополнение
нулями изменило бы функцию. Меняются только словарь и позиции:
- два новых эмбеддинга `THINK` и `LOOKUP` начинаются со среднего эмбеддингов `CALC` и
  `ANSWER`;
- таблица позиций пересчитывается под формат V2: начало наблюдения (страница) сохраняет свои
  позиции, конец (разговор, вопрос, черновик) — расстояние до конца, позиции ответа
  продолжаются.

**Проверка** (`grow::tests`): при том же формате и словаре выращенная модель даёт ту же ошибку
декодера на тех же примерах (совпадение до 1e-3). Реализация — `src/grow.rs`, запуск:

```bash
cog_engine train-unified --grow-from models/agent.safetensors --school data/school/chains.jsonl \
    --steps 8000 --batch 32 --out models/agent_l.safetensors
```

**M — с нуля.** 256 → 320 и 4 → 6 слоёв — не удвоение. Глубину можно нарастить точно, добавив
блоки с нулевыми выходными проекциями (они пропускают поток насквозь), но ширину 320 точно не
получить. Поэтому M проще учить с нуля по учебному плану раздела 4.

## 6. Вычисления

Замер на 4 ядрах CPU, без GPU:

- **base:** 0.47 шага/с при батче 64, то есть около 30 примеров/с. 10 000 шагов — 6 ч.
  Эффективность держится на трёх приёмах из [unified.md](unified.md): микробатчи по ядрам,
  настройка `malloc`, облегчённые блоки декодера.
- **Оценка для M и L.** Время примера растёт с числом параметров декодера (×1.9 и ×3.3), с
  вдвое длинными наблюдением и действием (×2) и с шириной TTT (скан по 384 токенам вместо 192):

| | примеров/с на 4 ядрах CPU (оценка) | 1 млн примеров-шагов |
|---|---:|---:|
| base | ~30 (замер) | ~9 ч |
| M | ~7 | ~40 ч |
| L | ~4 | ~70 ч |

Для L практичен GPU: graph path собирается с `--features cuda` (bf16), но на GPU ещё не
проверялся. На CPU реалистичный путь — M с нуля или L, выращенная из base, с дообучением
10–20 тыс. шагов.

## 7. Как проверять

| Что | Метрика |
|---|---|
| математика | точность ответа по ключу `check` на test (5 568 задач) по классам и темам; доля цепочек, где все CALC синтаксически верны; доля ответов, скопированных из результата последнего CALC |
| русский язык | точность по ключу на test: отложенные слова и предложения, по темам (часть речи, падеж, состав слова, склонение, спряжение, вид, причастие, деепричастие) |
| инструменты | доля эпизодов, где LOOKUP вызван для слова из вопроса; доля ответов, согласованных со статьёй словаря |
| браузер | успешность агента на 2 × 200 задачах (обучающие и отложенные формулировки), в симуляторе и в Chromium, — не хуже base |
| разговор | потери на токен на отложенных диалогах; ответы на фиксированный набор реплик |
| рассуждение | абляции: без латентного поиска (`--search 0`), без шагов THINK (сразу CALC или ANSWER) — насколько падает точность многошаговых задач |

## 8. Изменения в коде

1. `text`: спецтокены `THINK`, `LOOKUP` в конце словаря (8192, 8193); у `Bpe` — секция
   «хвостовых» спецтокенов.
2. `browser::action`: действия `Think { text }` и `Lookup { text }`; `ACTION_LEN = 64`.
3. `browser::obs`: черновик последних шагов вместо одной записи калькулятора;
   `OBS_LEN = 320`, `GOAL_MAX = 64`, `SCRATCH_MAX = 128`.
4. `tools::dictionary`: словарь из `dictionary.jsonl`, поиск без учёта регистра и `ё`.
5. `browser::agent`: `THINK` дописывает запись в черновик и не трогает браузер, `LOOKUP`
   вызывает словарь; учитель браузерных задач добавляет шаги THINK (как `export-trajectories`).
6. `dialog`: источник «школа» — загрузка `chains.jsonl` и разворачивание цепочек в примеры по
   шагам; учебный план по классам.
7. `speech`: масштаб логитов; `unified`: `grow(base → L)` по разделу 5; пресеты `m`, `l`
   (уже есть).
8. `unified-eval`: точность на школьном test по ключам `check`.

## 9. Риски и ограничения

* **Модель повторяет рассуждение, а не выводит его.** THINK-шаги взяты из шаблонов (по 1–3 на
  тему), и модель может выучить их как фразы. Проверка — отложенные темы и формулировки. Помочь
  может перефразирование шаблонов (по 5–10 вариантов на тему).
* **Язык SynTagRus взрослый** (новости, художественная проза). Задачи по предложениям трудны
  по лексике, хотя их грамматическая часть — школьная.
* **Морфемный словарь Тихонова защищён авторским правом.** Он используется только локально
  для обучения, в репозиторий не попадает. Разбор отражает словарь, а в школьных учебниках
  встречаются другие варианты (например, «-ть» как окончание или как суффикс).
* **Калькулятор без степеней и остатка.** Степени выражаются умножением, остаток — через
  `n − q · d`. Поэтому модель учится записывать решение через доступные операции.
* **Вычисления.** L на CPU учится днями. Без GPU реалистичен M или выращенная L с коротким
  дообучением.
