# Архитектура

## Общая схема

```
                       ┌──────────────────── обучение (graph path, candle + autograd) ────────────────────┐
                       │                                                                                  │
 prompt tokens ─► TTT-Encoder ─► S_prompt ─► E_θ ─► s_0 ─┬─► goal head ─► ĝ                              │
                  (W_fast)                               │                │                               │
                                                         └─► планировщик ◄┘  π(s, ĝ) + MPPI + P_φ(s, a)   │
                                                                  │                                       │
                                                                  ▼                                       │
                                               S_plan = [s_0, s_1, …, s_H]                                │
                                                                  │ cross-attention                       │
                                      X_0 ~ N(0, I) ─► ODE: dX = v_θ(X, t | S_plan) dt, t: 0 → 1 ─► X_1   │
                                                                                                      │   │
                                                                     tokens = argmax(W_head X_1) ◄────┘   │
                       └──────────────────── инференс (kernel path, bf16, 0 аллокаций) ───────────────────┘
```

Каждая стадия работает в своём пространстве представлений. У каждого пространства есть
NewType-обёртка (`src/types.rs`), и перепутать их нельзя.

| Пространство | Тип | Форма (пресет `tiny`) | Кто производит | Кто потребляет |
|---|---|---|---|---|
| токены | `&[u32]` | `[N]`, `[L]` | пользователь / head | TTT / пользователь |
| контекст | `PromptState` | `[d_ctx] = [96]` | TTT readout | `E_θ` |
| латентное состояние | `LatentState` | `[d_s] = [32]` | `E_θ`, goal head | планировщик |
| план | `LatentPlan` | `[H+1, d_s] = [5, 32]` | планировщик | векторное поле |
| поток | `FlowState` | `[L, d_token] = [8, 32]` | ODE-решатель | head |

## Три модуля

### 1. TTT-Encoder (`src/ttt/`)

Каждый токен превращается в вектор: `эмбеддинг токена + позиционный эмбеддинг + эмбеддинг сегмента`.
Сегмент 0 — промпт, сегмент 1 — продолжение-ответ (нужен при обучении). Затем слой TTT-Linear
проецирует вектор в ключ `k`, значение `v` и запрос `q` и делает **один шаг градиентного спуска**
по `W_fast`, чтобы `W_fast·k ≈ v`. Никакого KV-кэша нет: после `N` токенов вся информация о
контексте лежит в `W_fast` (`32×32` float = 4 KiB в `tiny`).

`S_prompt` читается из `W_fast` обучаемыми пробами `P` и средним выходов слоя `z_t = W_t q_t`,
затем проходит через MLP.

Две опции (по умолчанию выключены, включены для задачи `browser`): `conv_width > 1` считает
`k, v, q, η` из короткого каузального окна последних токенов, так что одно обновление связывает
соседние токены; `readout_last > 0` добавляет в readout выходы `z_t` последних токенов, и вопрос в
конце промпта работает как ассоциативный запрос к `W_fast`.

| Файл | Что внутри |
|---|---|
| `fast_weights.rs` | `FastWeightsState` — сама матрица и шаг обновления; батчевые дифференцируемые версии для обучения |
| `layer.rs` | `TttLinear` (проекции θ_K, θ_V, θ_Q и гейт адаптивного η), `scan` по последовательности, упакованная версия |
| `mod.rs` | `TttEncoder` (эмбеддинги + слой + readout) и `PackedTttEncoder` с потоковым API `absorb`/`finish` |

Потоковый API позволяет подавать контекст **любой длины**. Позиции за пределами обученной
таблицы используют её последнюю строку.

### 2. JEPA-планировщик (`src/jepa/`)

«System 2» работает только в `ℝ^{d_s}`. Токенов на этой стадии нет вообще.

| Компонент | Назначение | Где используется |
|---|---|---|
| `E_θ` (`ctx_enc`) | `S_prompt → s_0` | обучение + инференс |
| `Ē_θ` (`target_enc`) | EMA-копия `E_θ`, кодирует цели | только обучение |
| `P_φ` (`world`) | `s_{t+1} = s_t + MLP([s_t; a_t])` | обучение + инференс (роллауты MPPI) |
| `A_ψ` (`inverse`) | выводит действие из пары состояний `(ŝ_t, s̄_{t+1})` | только обучение |
| `G_ω` (`goal`) | `ĝ = s_0 + G(s_0)` — куда должно прийти рассуждение | обучение + инференс |
| `π` (`policy`) | `a = π(s, ĝ)` — предложение действия | обучение (BC) + инференс (тёплый старт) |

На инференсе `JEPAPlanner` ищет последовательность действий `a_0 … a_{H−1}`. Её роллаут через
`P_φ` должен закончиться около `ĝ`. Порядок такой: роллаут политики даёт начальную гипотезу,
затем MPPI уточняет её, параллельно проигрывая `M` возмущённых траекторий. Опционально
результат доводится градиентным спуском (`GradientPlanner`).

| Файл | Что внутри |
|---|---|
| `world_model.rs` | `WorldModel` (graph) и `PackedWorldModel` (ядра, `step`, `rollout`) |
| `vicreg.rs` | invariance / variance / covariance |
| `planner.rs` | `JEPAPlanner` (MPPI), `MppiWorkspace`, `PlanStats`, `GradientPlanner` |
| `mod.rs` | `Jepa` — все обучаемые части, `forward_train`, EMA, упаковка |

### 3. CFM-декодер (`src/flow/`)

Векторное поле `v_θ(X_t, t, S_plan)` — это маленький DiT. На вход идут все `L` позиций ответа
сразу. Время `t` и сводка плана подаются через adaLN-Zero-модуляцию, а сам план — через
cross-attention. ODE-решатель (Euler / Midpoint / Heun) за `K` шагов переносит гауссов шум в
эмбеддинги ответа. Затем головка превращает все позиции в токены за один проход.

| Файл | Что внутри |
|---|---|
| `vector_field.rs` | `VectorField` (graph), `PackedVectorField` (ядра + собственный workspace), `GraphVectorField` (эталон на candle) |
| `ode_solver.rs` | трейт `VectorFieldEstimator`, `FlowMatchingSampler`, `SamplerBuffers`, `SolverKind` |
| `mod.rs` | `ot_path` (путь и целевая скорость), `UnembedHead`/`PackedHead`, батчевый `sample_graph` |

## Два пути исполнения

Обе версии каждого модуля читают **одни и те же параметры**. Упаковка — это копия с
понижением точности. Что оба пути считают одно и то же, проверяют тесты паритета
(см. [development.md](development.md)).

| | graph path | kernel path |
|---|---|---|
| Где | `forward`, `forward_train`, `loss`, `sample_graph` | `Packed*`, `CognitiveEngine`, `JEPAPlanner::plan_into` |
| Вычисления | операции candle, autograd | собственные ядра на срезах `f32` (`src/kernels/`) |
| Устройство | CPU или CUDA (фича `cuda`) | CPU |
| Веса | `f32`-мастер-копии в `Var`, приводятся к compute dtype | упакованы в `bf16` (или `f16`/`f32`), аккумуляция в `f32` |
| Батч | да, `[B, …]` | один запрос за раз |
| Аллокации | на каждую операцию | ноль после создания движка |
| Назначение | обучение, оценка по оракульному плану | инференс, бенчмарки, сервер |

Мост между путями — `pack(dtype)` у каждого модуля и `CognitiveEngine::from_model(&CogModel)`.
`from_model` упаковывает все модули и выделяет все буферы в одной `Arena`.

## Жизненный цикл запроса в `CognitiveEngine::generate_into`

1. **encode.** `PackedTttEncoder::encode` обнуляет `W_fast` и для каждого токена вызывает `absorb`:
   эмбеддинг → LayerNorm → проекции `k, v, q` → η_t → фьюзнутый шаг `W ← W − η(Wk − v)⊗k` →
   `z = Wq`. Затем `finish` делает readout в тензор `S_prompt`, принадлежащий арене.
2. **think.** Сначала `s_0 = E(S_prompt)` и `ĝ = s_0 + G(s_0)`. Затем `JEPAPlanner::plan_into`
   (роллаут π, потом итерации MPPI) пишет план в `MppiWorkspace::plan`. В режиме `MppiThenGradient`
   дополнительно запускается `GradientPlanner::refine`; результат принимается, только если энергия
   стала ниже.
3. **decode.** `FlowMatchingSampler::sample_into` заполняет `X_0` шумом и вызывает
   `PackedVectorField::prepare`: он один раз проецирует план в K/V cross-attention для каждого слоя.
   Затем идут `K` шагов решателя, и `PackedHead::decode_into` превращает `X_1` в токены.

Все промежуточные данные лежат в буферах, выделенных при создании движка. Состав памяти
(`CognitiveEngine::memory()`):

| | `tiny` | `small` |
|---|---:|---:|
| Упакованные веса (bf16) | 589 KiB | 3.0 MiB |
| Арена (активации, состояния, scratch) | 228 KiB в 58 буферах | 829 KiB в 60 буферах |
| `W_fast` — вся память контекста | 4 KiB | 16 KiB |

## Карта исходников

```
src/
├── lib.rs            — корень крейта, реэкспорт главных типов
├── main.rs           — CLI: demo / train / infer / bench / serve / agent / agent-eval / site
├── config.rs         — EngineConfig (+ TTT/JEPA/Planner/Flow), TrainConfig, пресеты, validate()
├── types.rs          — PromptState, LatentState, LatentPlan, FlowState
├── arena.rs          — Arena: учёт и выдача предвыделенных буферов
├── nn.rs             — ParamStore (детерминированная инициализация, save/load), Lin, Mlp, LN, MHA
├── kernels/
│   ├── mod.rs        — PackedLinear/PackedMlp, WeightBuf, поэлементные и строковые ядра, attention, rank-1
│   ├── simd.rs       — dot / dot4 на AVX2+FMA(+F16C) с runtime-детекцией; единственный unsafe
│   ├── inplace.rs    — изменение тензоров candle на месте через InplaceOp1/2/3
│   └── rng.rs        — xoshiro256++, независимые потоки, нормальное распределение
├── ttt/              — модуль 1
├── jepa/             — модуль 2
├── flow/             — модуль 3
├── model.rs          — CogModel: все модули + совместная функция потерь + чекпойнты
├── train.rs          — Trainer, EvalReport с абляциями планировщика
├── data.rs           — задачи sort / reverse / copy / browser
├── pipeline.rs       — CognitiveEngine: инференс Tokens → Tokens
└── browser/          — агент-браузер (docs/browser.md)
    ├── chrome.rs, cdp.rs — Chromium через DevTools: свой WebSocket, клики, ввод, история
    ├── world.rs, server.rs — песочница: поисковик и страницы товаров, HTTP-сервер
    ├── sim.rs        — симулятор браузера с тем же DOM (данные для обучения)
    ├── obs.rs, vocab.rs — страница + цель → 24 токена; словарь, действия, разбор вопроса
    ├── expert.rs, data.rs — учитель и обучающие состояния
    └── agent.rs      — цикл «наблюдение → действие», эпизоды, оценка
```
