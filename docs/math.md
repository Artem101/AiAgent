# Математика

Все формулы ниже соответствуют коду один в один. Рядом с каждой указано, где она реализована.
Обозначения: `sg(·)` — stop-gradient (`detach`), `LN` — LayerNorm без обучаемых параметров,
`MLP(x) = W₂·GELU(W₁x + b₁) + b₂`, GELU — tanh-аппроксимация.

## 1. TTT-Encoder

### Вход

Для токена `y_t` на позиции `t` с сегментом `σ` (0 — промпт, 1 — ответ):

```
x_t  = E_tok[y_t] + E_pos[min(t, P−1)] + E_seg[σ]            ttt/mod.rs  embed / absorb
x̃_t = LN(x_t)
k_t  = θ_K x̃_t / ‖θ_K x̃_t‖        v_t = θ_V x̃_t        q_t = θ_Q x̃_t / ‖θ_Q x̃_t‖
η_t  = η · sigmoid(w_η·x̃_t + b_η)   (при adaptive_lr = false: η_t = η)        ttt/layer.rs  project
```

Нормы считаются с `ε = 1e-6` под корнем.

### Внутренний цикл: онлайн-градиентный спуск по быстрым весам

Самообучаемая функция потерь — реконструкция значения по ключу:

```
ℓ(W; x_t) = ½ ‖W k_t − v_t‖²          ∇_W ℓ = (W k_t − v_t) ⊗ k_t
```

Один шаг градиентного спуска на каждый токен, `W_0 = 0`:

```
W_t = W_{t−1} − η_t (W_{t−1} k_t − v_t) ⊗ k_t                ttt/fast_weights.rs  step_update
z_t = W_t q_t                                                 (выход слоя)
```

**Почему это устойчиво.** Так как `‖k_t‖ = 1`, после шага

```
W_t k_t = (1 − η_t) W_{t−1} k_t + η_t v_t
```

— выпуклая комбинация старого ответа и нового значения при `η_t ∈ (0, 1]`. Норма `W` не может
разойтись ни при какой длине контекста. При `η_t = 1` ключ отображается в значение точно (это
проверяет тест `rank1_update_is_gradient_step`).

**Фьюзнутое ядро.** Строке `i` матрицы нужна только её собственная невязка
`e_i = W_i·k − v_i`. Поэтому обновление `W_i ← W_i − η e_i k` делается за один проход по
строкам, без временного буфера, и строки независимы (`kernels::rank1_update`).

### Readout

Обучаемые пробы `P ∈ ℝ^{d_fast × r}` «опрашивают» память:

```
S_prompt = MLP_readout( LN( [ vec(W_N P) ; (1/N) Σ_t z_t ] ) )          ttt/mod.rs  readout / finish
```

Размер входа — `d_fast·r + d_fast` (288 в `tiny`), выхода — `d_ctx`. Память O(d_fast²) и не
зависит от `N`.

## 2. JEPA: латентная модель мира

### Модули

```
s_0      = E_θ(S_prompt)                               (ctx_enc)
ŝ_{t+1}  = P_φ(ŝ_t, a_t) = ŝ_t + MLP_φ([ŝ_t ; a_t])     (world, резидуальная)
a_t      = tanh(MLP_ψ([ŝ_t ; s̄_{t+1}]))                (inverse — модель латентных действий)
ĝ        = s_0 + MLP_ω(s_0)                            (goal)
π(s, g)  = tanh(MLP_π([s ; g]))                        (policy)
```

### Откуда берутся цели

При обучении ответ дописывается к промпту, и TTT продолжает сканирование. Ответ длины `L` делится
на `H` чанков по `c = L/H` токенов. После промпта и после каждого чанка снимается readout:

```
S_h = readout(W после N + h·c токенов),   h = 0 … H                model.rs  readouts
s̄_h = sg( Ē_θ( sg(S_h) ) )                                        jepa/mod.rs  forward_train
```

`s̄_0` кодирует только вопрос, `s̄_H` — вопрос вместе с полным ответом. Промежуточные цели —
«частично решённая задача». Рассуждение моделируется как путь в латентном пространстве от
вопроса к ответу.

### Teacher-forced роллаут

```
ŝ_0 = s_0
для t = 0 … H−1:   a_t = tanh(MLP_ψ([ŝ_t ; s̄_{t+1}]))
                   ŝ_{t+1} = P_φ(ŝ_t, a_t)
```

`A_ψ` видит следующую цель, поэтому действие кодирует, «какой шаг сделать». Размерность
`d_a = 8` и tanh ограничивают, сколько информации может пройти через действие. Траектория
`[ŝ_0 … ŝ_H]` (с шумом `N(0, 0.05²)`) — это план, на котором обучается декодер.

### Потери JEPA

VICReg усредняется по всем `h = 0 … H` (`jepa/vicreg.rs`):

```
Inv_h = MSE(ŝ_h, s̄_h)
Var_h = (1/d) Σ_j max(0, γ − sqrt(Var_batch(ŝ_h[:, j]) + ε))          γ = 1, ε = 1e-4
Cov_h = (1/d) Σ_{i≠j} C_ij²,   C = (Z − Z̄)ᵀ(Z − Z̄)/(B − 1),  Z = ŝ_h
```

Сумма внедиагональных квадратов вычисляется как `Σ C² − Σ diag(C)²`, где диагональ — уже
посчитанная дисперсия.

```
L_goal = MSE(ĝ, s̄_H)
L_π    = (1/H) Σ_t MSE( π(sg(ŝ_t), sg(ĝ)), sg(a_t) )                   (behaviour cloning)
L_JEPA = λ_inv·Inv + λ_var·Var + λ_cov·Cov + λ_goal·L_goal + λ_π·L_π
```

Веса по умолчанию: `λ_inv = 1`, `λ_var = 0.5`, `λ_cov = 0.04`, `λ_goal = 1`, `λ_π = 1`.

Политика обучается на `ĝ`, а не на истинной цели `s̄_H`. Так распределение её входов при обучении
совпадает с инференсом.

### EMA целевого энкодера

После каждого шага оптимизатора (`Jepa::ema`, `τ = ema_decay = 0.99`):

```
θ̄ ← τ θ̄ + (1 − τ) θ
```

При создании модели `θ̄ = θ`.

## 3. Планирование на инференсе

### Энергия

```
E(A) = (1/d_s) ‖s_H(A) − ĝ‖² + λ_a · (1/(H·d_a)) ‖A‖²          jepa/planner.rs  energy
```

Здесь `s_H(A)` — конец роллаута `P_φ` из `s_0` под действиями `A = [a_0 … a_{H−1}]`, а
`λ_a = action_cost = 0.01`. Второй член держит действия в той области, где обучалась модель.

### Тёплый старт

Если политика подключена и `policy_prior = true`, номинал строится роллаутом политики. Иначе
номинал нулевой.

```
s ← s_0;  для t:  U_t = π(s, ĝ);  s ← P_φ(s, U_t)
```

`initial_energy = E(U)` запоминается как точка отсчёта.

### MPPI (`JEPAPlanner::plan_into`)

Для итерации `i = 0 … iterations−1`:

```
σ_i   = noise_std · noise_decay^i
для m = 0 … M−1 (параллельно):
    ε_m = 0 при m = 0 (номинал всегда среди кандидатов),  иначе ε_m ~ N(0, σ_i² I)
    A_m = clip(U + ε_m, −1, 1)
    E_m = E(A_m)                                  (роллаут H шагов через P_φ)
λ'    = temperature · (mean E − min E)            при normalize_costs, иначе temperature
w_m   = exp(−(E_m − min E)/λ') / Z                (веса path integral)
U     ← Σ_m w_m A_m
ESS   = 1 / Σ_m w_m²                              (эффективное число сэмплов)
```

Лучший сэмпл за все итерации запоминается. После итераций план — это роллаут номинала `U`.
Если какой-то сэмпл был строго лучше, берётся он. Поэтому **энергия результата никогда не хуже
тёплого старта**.

Нормированная температура делает `λ'` инвариантной к масштабу энергий. При
`temperature = 0.1` значимый вес получают сэмплы, чья стоимость отличается от минимальной не
больше чем на несколько десятых от «типичного разброса».

**Детерминизм.** Шум сэмпла `m` на итерации `i` генерируется потоком `Rng::stream(seed, i, m)`.
Редукции (минимум, веса, взвешенное среднее) выполняются последовательно. Поэтому результат
бит-в-бит не зависит от числа потоков.

### Latent GD (`GradientPlanner::refine`)

Параметризация `A = tanh(u)`, старт `u = atanh(clip(U_MPPI, ±0.999))`. Затем `gd_steps` шагов
Adam (`lr = gd_lr`, без weight decay) по той же энергии `E` через дифференцируемую `P_φ`.
Результат принимается, только если энергия снизилась.

## 4. CFM-декодер

### Данные и путь

Цель потока — эмбеддинги ответа из **замороженной** случайной таблицы: `X_1 = E_out[y] ∈ ℝ^{L×d_token}`,
`E_out ~ N(0, 1)`. Замороженные цели не дают CFM коллапсировать их в одну точку.

Условный OT-путь (`flow::ot_path`), `X_0 ~ N(0, I)`, `t ~ U[0, 1)`:

```
X_t = (1 − (1 − σ_min) t) X_0 + t X_1          u_t = X_1 − (1 − σ_min) X_0          σ_min = 1e-4
L_CFM = MSE( v_θ(X_t, t, S_plan), u_t )
```

### Вспомогательные потери

```
x̂_1    = X_t + (1 − t) v_θ(X_t, t, S_plan)          (одношаговая оценка чистого сэмпла)
L_ce    = CE( W_head x̂_1 + b, y )
L_head  = CE( W_head (X_1 + 0.1 ε) + b, y )           (головка учится на слегка зашумлённых целях)
```

### Векторное поле (`flow/vector_field.rs`)

```
e(t)  = [cos(1000t·f_i) ; sin(1000t·f_i)],   f_i = exp(−ln(10⁴)·i/(d_time/2))
c     = W_t2 · SiLU(W_t1 e(t)) + W_pool · mean_p(S_plan)          (глобальное условие)
h     = W_in X_t + pos                                             [L, d_h]
mem   = W_plan S_plan + plan_pos                                   [H+1, d_h]

блок (adaLN-Zero):  [β₁, γ₁, α₁, β₂, γ₂, α₂] = W_mod · SiLU(c)     (W_mod инициализирована нулём)
    h += α₁ ⊙ SelfAttn( LN(h)(1 + γ₁) + β₁ )
    h += CrossAttn( Q = LN(h), K = V = mem )
    h += α₂ ⊙ MLP( LN(h)(1 + γ₂) + β₂ )

v     = W_out ( LN(h)(1 + γ_f) + β_f ),   [β_f, γ_f] = W_fmod · SiLU(c)   (W_fmod, W_out — нулевая инициализация)
```

При нулевой инициализации модуляций каждый блок в начале обучения — тождество, а выход поля
равен нулю. Это стандартный приём DiT для стабильного старта.

Внимание многоголовое (`n_heads = 4`), масштаб `1/sqrt(d_h/n_heads)`. Softmax и LayerNorm
считаются в f32. K/V cross-attention не зависят от `t`, поэтому kernel path вычисляет их один
раз на траекторию (`prepare`).

### Интегрирование (`flow/ode_solver.rs`)

`dt = 1/K`, `t_k = k·dt`:

```
Euler:     X ← X + dt·v(X, t)
Midpoint:  X ← X + dt·v( X + (dt/2)·v(X, t),  t + dt/2 )
Heun:      X̃ = X + dt·v(X, t);   X ← X + (dt/2)·( v(X, t) + v(X̃, t + dt) )
```

Для `v = −x` тест `solvers_converge_with_expected_order` проверяет порядок сходимости: Euler —
первый, Midpoint и Heun — второй.

### Токены

```
tokens_i = argmax_v (W_head X_1[i] + b)_v          для всех i = 1 … L за один проход
```

## 5. Полная функция потерь

```
L = L_CFM + λ_ce·L_ce + λ_head·L_head + L_JEPA          model.rs  CogModel::loss
```

`λ_ce = λ_head = 0.2`. Градиенты идут сквозь всю цепочку: CFM → план → `P_φ`, `A_ψ`, `E_θ` → TTT.
Исключения — целевая ветка (`sg`) и входы политики.
